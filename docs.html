Documentation

MeetBuddy is a privacy-first AI meeting recorder. It captures, transcribes, and understands your calls without joining as a bot — runs entirely on your machine or self-hosted on your own server.

Overview #

MeetBuddy gives you two ways to capture audio, feeding the same backend pipeline:

  • Chrome Extension — captures tab audio via chrome.tabCapture and your mic via getUserMedia. Works on Google Meet; streams chunks in real time over WebSocket.
  • Desktop Tray App — uses PipeWire at the OS level to capture mic + speaker output simultaneously. Works with any platform — Zoom, Teams, Meet, or any app that uses your speakers.

Both paths feed the same Celery pipeline: faster-Whisper transcribes the audio, sentence-transformers generate pgvector embeddings, and an LLM extracts summaries, decisions, and action items.

ℹ️ Your meeting data never leaves your machine unless you explicitly configure a cloud LLM provider (OpenAI, Anthropic, Groq). With Ollama as the provider, everything is 100% local.

Quick Start #

1

Clone and configure

Copy the example env file and fill in at minimum JWT_SECRET and NEXTAUTH_SECRET.

2

Start infrastructure

Spins up Postgres, Redis, MinIO, the FastAPI server, and the Celery worker.

3

Start the web dashboard

Next.js dev server on localhost:3000.

4

Create an account and grab your token

Register at localhost:3000 — you'll need the JWT for the tray app or extension settings.

# 1. Clone and configure
git clone https://github.com/AyushAhire/meetbuddy.git
cd meetbuddy
cp .env.example .env   # edit JWT_SECRET, NEXTAUTH_SECRET, LLM key

# 2. Start infra + API + worker
./scripts/start.sh

# 3. Start web dashboard
cd apps/web && pnpm dev

# 4. Open http://localhost:3000 → register → copy your token

Chrome Extension #

The extension uses chrome.tabCapture for speaker audio and getUserMedia for your microphone. It's built with Plasmo (Chrome MV3).

Build and load

# Build in watch mode
cd apps/extension && pnpm dev
  1. Go to chrome://extensions
  2. Enable Developer mode (top-right toggle)
  3. Click Load unpacked → select apps/extension/.plasmo/chrome-mv3-dev

First use

Navigate to a Google Meet tab. Click the MeetBuddy icon in the toolbar. Open Settings and paste your JWT from the dashboard, then click Start Recording.

💡 The extension streams audio chunks over WebSocket to /api/v1/ws/{"{meeting_id}"} in real time, so transcription starts processing before the meeting ends.

Desktop Tray App #

The tray app uses PipeWire's pw-record to capture both your microphone and the speaker output (sink monitor) at the OS level. This works with any meeting platform — not just Chrome tabs.

Install dependencies

pip install pystray pillow pywebview
# httpx is already installed via apps/api requirements

Launch

# Launch the tray app (persists across sessions)
DISPLAY=:0 PYSTRAY_BACKEND=xorg python3 apps/tray/tray.py

Left-click the tray icon to open the in-app window. On first launch, open Settings and paste your JWT token from the dashboard.

Run the capture daemon directly

You can also run the daemon headlessly and control recording from the web UI:

# Start daemon (controlled from localhost:3000)
python3 apps/capture/capture.py --daemon

# Or one-shot from CLI — Ctrl+C stops and auto-uploads
python3 apps/capture/capture.py --token <jwt>

Run as a systemd service

A service file is included at scripts/meetbuddy-capture.service for running the capture daemon on login.

# Copy and enable the user service
cp scripts/meetbuddy-capture.service ~/.config/systemd/user/
systemctl --user enable --now meetbuddy-capture

Audio Device Setup #

By default MeetBuddy auto-selects your default mic and the default output monitor. To use specific devices:

# List available PipeWire nodes
python3 apps/capture/capture.py --list

# Override specific devices
python3 apps/capture/capture.py \
  --mic "alsa_input.pci-0000_00_1f.3.analog-stereo" \
  --monitor "alsa_output.pci-0000_00_1f.3.analog-stereo.monitor"
⚠️ PipeWire is required for the tray app. On Ubuntu 22.04+ and most modern distros it's pre-installed. On older systems you may need to install pipewire and pipewire-audio and restart the session.

LLM Providers #

All LLM calls are routed through apps/api/services/llm.py. Switch providers by setting LLM_PROVIDER in your .env.

ProviderValueWhat you need
Ollama (default) ollama Ollama running locally. Pull a model first: ollama pull llama3
Anthropic anthropic Set ANTHROPIC_API_KEY in .env
OpenAI openai Set OPENAI_API_KEY in .env
💡 Free option: Set GROQ_API_KEY to use Groq's free tier for both transcription (Whisper) and inference (Llama 3) with a single API key and very low latency.

Architecture #

Both capture methods feed the same Celery pipeline. Here's the full data flow:

Option A — Desktop tray app
PipeWire (mic + monitor)
  └─► capture.py daemon  :7779
        └─► POST /api/v1/upload

Option B — Chrome extension
tabCapture + getUserMedia
  └─► WebSocket /api/v1/ws/{"{meeting_id}"}

Both paths →
Celery pipeline
  ├─ faster-whisper  ──► transcript segments
  ├─ sentence-transformers  ──► pgvector embeddings
  └─ LLM (Ollama / Anthropic / OpenAI)
       └─► summary + action items + decisions
                │
                ▼
     Next.js dashboard  (meetings, search, insights)

Contributing #

MeetBuddy is open source and contributions are very welcome. The project is early-stage so there's lots of room to make a real impact.

Good first areas

  • Fixing issues labeled good first issue on GitHub
  • Adding support for more meeting platforms in the extension
  • Improving the Next.js dashboard UI
  • Writing tests for the FastAPI routes
  • macOS or Windows support for the tray app (currently Linux-only)

Dev workflow

# Fork → clone → create a branch
git checkout -b feat/your-feature

# Make changes, then open a PR against master
git push origin feat/your-feature

Please keep PRs focused — one feature or fix per PR makes review much faster.
